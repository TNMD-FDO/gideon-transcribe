The Upload page, reorganised: a fault found, and the page tightened

Measured on the local office at a 1366 x 768 laptop window (724 pixels of page) and at 1912 x 1000. The spec's layout from 1280 pixels is Choose files on the left, Settings over Check and start on the right, with Upload and transcribe always in view. The page has not read that way since v1.174.0: its step list is opened twice in the template, so the three steps are laid out inside the left half of the page, every card is half its width, every caption wraps, and the page runs 1,221 pixels tall with the start button at 1,100. Figure A is the page as it is, Figure B the same page with the one line fixed, Figure C the fixed page tightened, which is the recommendation.

The captions, as agreed 2026-11-02. The start pinned. Check and start keeps its review table; its last row, the count, the size and the start button, is pinned to the bottom of the window while the page is taller than it (the stepper already pins the step's buttons below 1280, in the same way), so Upload and transcribe is always in view as the spec asks. Smaller words up top. The lead sentence sits beside the title on one line and takes "Nothing leaves this building" with it from the foot; "Which files" is a link on the limits line rather than a fold of its own; More options names what it holds. Why not. Three columns at 1366 are 370 pixels each, which is the width that made every caption wrap in Figure A; the file cards with their names, sizes and chips wrap too, and the review table loses its original-name column. At 1912 it reads well, but the office's laptops are the case that matters. The start button is in view only because the third column is short; a batch of eight files pushes the review table past the fold again.

Not drawn: one step at a time on every width. The stepper below 1280 does this already; above it the spec chose all three at once so the page is read in one glance, and nothing in the measurement argues against that once the fault is fixed.
