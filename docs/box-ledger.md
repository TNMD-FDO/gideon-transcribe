# The box ledger

**Rules version:** 2026-10-15.2 (sections 1 to 11)
**Copies:** `docs/box-ledger.md` in `TNMD-FDO/GIDEON-dev` (GIDEON's development repository, private) and `docs/box-ledger.md` in `TNMD-FDO/gideon-transcribe`. The public `TNMD-FDO/GIDEON` omits `docs/box-ledger.md` from its export (since `v0.1.74`); it is never the copy fetched. Sections 1 to 11 are one text in both; section 12 is a log with one subsection per project, each written only by that project. Nobody writes into the other project's repository: each project fetches the other's copy and merges it (§11).

Two projects run on one server and in one GitHub organisation: GIDEON, the platform and legal-AI product, and Gideon Transcribe, the transcription app. Each has its own repository, install home, release rule, and operator. Each application can be installed first, and each keeps working without the other. The hardware profile GIDEON is sized for leaves a co-tenant reserve; where agreed allocations collide, GIDEON's allocation is met first. They share the hardware, the Docker daemon, the host firewall, the engine, and the organisation's pool of hosted-runner minutes. This ledger records what each project shares, what each may do with it, the events one project must announce to the other, and, in its log, what each project changed and what it recommends to the other. It states keys, defaults, paths, and units. It never states an office value: no hostname, address, network range, account name, or storage target appears here, because both repositories are written as if public.

The facts below were read from the two repositories and from the running server on the ledger's date. A number marked *observed* is what the server showed that day, not a commitment.

**Precedence.** Where the two need the same allocation — a card's memory, the hosted-minute pool, a port, a directory, the disk — GIDEON's need is met first and Transcribe fits into what remains. A reserve the hardware profile leaves for a co-tenant is what Transcribe may count on today, and anything beyond it is on loan until GIDEON needs it. Precedence is not licence to break Transcribe without notice: the announce-before list (§8) stands, taking back a loan is a rules change here first with the notice a maintenance window gets, and a running application is left running until its stop or replacement is agreed.

**Direction and request.** The same allocation precedence runs through the log (§12). A line GIDEON addresses to Transcribe about an agreed allocation or a change to it is a direction: Transcribe's agents fit their next change to it and answer by number with what changed and when, or, when it cannot be followed, with the reason, within the notice a maintenance window gets, so the two operators can settle it. A line Transcribe addresses to GIDEON is a request that GIDEON weighs and answers. Transcribe's own product decisions stay its own where they touch nothing shared.

## 2. The host layer, shared

The first application to need one installs it when absent; either accepts it when present and sufficient. A person upgrades one in an announced maintenance window by the recipe, and neither application removes one. Where GIDEON's code does not yet follow a rule below, the row or rule names the GIDEON cotenancy ticket that brings it; until it lands, GIDEON's step behaves as before, and its §12 entry says when it does.

**Rules**

- A shared prerequisite is installed when absent by the recipe above, accepted when present and sufficient, upgraded only by a person in an announced window by that recipe, and removed by neither application.
- Each application touches only paths carrying its ownership mark, an absent shared prerequisite by the recipe, or a box-wide setting still at its default. A directory, unit, or rule without its mark is not its to create, own, or remove. State without the mark is kept and reported.
- A moved box-wide setting is checked and never changed. A shortfall refuses with the fix.
- The hardware profile leaves a co-tenant reserve on a named card for whatever co-tenant an office installs; each application checks free memory on that card before a start that would take memory there (§3).

With Transcribe's local vLLM on, Transcribe holds about 45 GB of GPU 1 at peak, the reserve's 24 GB and that engine's 21 GB; GIDEON's plan with everything on is 94 GB, already including the same reserve, so the two figures are not added. The combined footprint is 69 GB at `v0.4.0` (`gideon-embed`'s 24 GB and Transcribe's 45 GB), 91 GB with the rerankers, and 115 GB with the bulk-embed profile on; the card's 96 GB is passed only when that profile runs beside Transcribe's local engine. The two shapes: Transcribe turns its local engine off (`./transcribe engine local off`) and uses GIDEON's engine on GPU 0 as a client, which frees 21 GB and costs nothing on GPU 0; or GIDEON's reserve rises to 45 GB and its bulk-embed profile stays off, which is a spec change on GIDEON's side. Under the precedence rule (§1) the default is the first shape: the 24 GB reserve is what Transcribe may count on, the local engine's 21 GB is on loan until GIDEON's bulk-embed profile needs the card, and GIDEON raises the reserve only if it chooses to.

**Rules**

- Each project's memory on each card is its line in the table above. Taking more, or taking memory on a card the table gives the other project, is a ledger change first and a maintenance-window change second.
- Each application checks free memory on the card before a start that would take memory there (GIDEON's from cotenancy ticket 13).
- A memory fraction is a release constant on GIDEON's side and an `.env` key on Transcribe's. Neither is changed on the server by hand.
- The engine on GPU 0 is GIDEON's service, arbitrated by its priority scheduler at every hour (ADR-0064): GIDEON's requests carry no priority and run first; a client's carry `priority` 1 or higher, run slowed while a GIDEON batch holds, and are never refused. What GIDEON's batches take of the sequence cap and the client reserve of the rest are figures of GIDEON's hardware profile. GIDEON's quiet window (§7) is its own rule about its users and binds no client. GPU 1 is bound by no window: `gideon-embed`, and the bulk embed through it, may load the card at any hour inside GIDEON's line (§7).

**Host RAM.** The host has 265.5 GB (247.3 GiB, *observed* 2026-10-04 in `.scratch/slice-3/assets/09-memory-and-gpu1.txt`) and 32 GiB of swap. A project's line is the sum of its Compose memory limits — ceilings against a runaway, never use — each limit carrying Docker's default swap allowance of the limit again, save a store's, whose block carries a swap ceiling one 4 KiB page above its limit so its resident index is never paged out (GIDEON's `qdrant` from `v0.3.35` and `opensearch` from `v0.3.37`, slice-3 tickets 10 and 12, and its sibling's two from `v0.3.44`, slice-3 ticket 19). The lines may pass the host: from `v0.4.0`, GIDEON's 261 GB in production and about 275 GB with its sibling stand beside Transcribe's 47 GB, about 322 GB in all against the host's 265.5 GB. The measure both projects hold to is the host's available memory on GIDEON's Prometheus, `node_memory_MemAvailable_bytes`, by its fourteen-day minimum (`min(min_over_time(node_memory_MemAvailable_bytes[14d]))`): 238.3 GB available at the reading and a fourteen-day low of 215.3 GB (*observed* 2026-10-04, same asset), against a floor of 53 GB, a fifth of the host. At that reading the fourteen-day working-set peaks summed to 17.1 GB for GIDEON, 1.1 GB for its sibling, and 16.8 GB for Transcribe (*observed* 2026-10-04, same asset); the lines remain ceilings, not use. When the low falls under the floor, the rows are re-weighed, changed in this ledger first, and then released on the side whose row moves. **Rules**

## 8. Announce before

An announcement is a message to the other operator before the event, with the hour, and a word after it, and a line in this ledger's log (§12) when the event changes a table above. For a maintenance window it is at least one working day ahead.

**Both announce**

- An upgrade of a shared prerequisite is done by a person in an announced maintenance window, by §2's recipe; whoever does it announces it.

**GIDEON announces**

- `host provision` on a live server when a step it will apply touches a shared prerequisite or a box-wide setting, since that restarts or reboots every container. A provision that installs nothing shared and moves no setting is announced to no one.
- `apply` when `images.lock` or the engine's configuration moved: the engine restarts and Transcribe's assistant, its client, sees an outage of about three minutes; `apply` recreates `gideon_gideon` only after a change to its definition, announced, and only once the client has left it — it cannot drop a client.
- Any change to the engine's API key: a client of the engine holds a copy.
- `upgrade`, `restore`, and `upgrade --rollback`: the whole GIDEON stack goes down and up.
- The acceptance runs at a minor tag, one after the other: the install run, about 20 minutes, then the full restore of the newest backup set, about 20 minutes more and about four copies of the set written under `/data/acceptance`; each an 8-vCPU, 16 GB VM, with the registry and the runner busy.
- `models pull` for a new profile: tens of gigabytes into `/data/models`.
- An engine batch of GIDEON's is announced to no one: a client's requests run slowed while a GIDEON batch holds and are never refused, under §7's terms.
- A batch on GPU 1 or the disks projected past an hour — the bulk embed, a corpus ingest, an index build — with its start and projected finish; the bounded runs of GIDEON's slice-3 tickets 26 to 43, over a part of tranche 1, are announced to no one.
- A supporting model's arrival on GPU 1 (§3): `gideon-embed` arrived at `v0.3.41` (§12), ahead of the `v0.4.0` slice; the rerankers come in the slice after it.

**Transcribe announces**

- `./transcribe engine local on` or `off`: 21 GB of GPU 1 taken or freed.
- Joining or leaving GIDEON's engine network, and the token hand-off that comes with it.
- A long transcription batch, or any run that holds WhisperX's 20 GB for hours. A batch of Transcribe's own over the engine is announced to no one, running at `priority` 1 or higher under §7's terms.
- A release that changes its published port, bind address, or a Compose network.
- Its restore drill outside its timer's hour, and any upgrade on this server.
- A build on the server, and the prune that follows it.
- A change to its workflow triggers that moves hosted-minute load, since the pool is shared (§9).
